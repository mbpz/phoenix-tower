## 二、产品逻辑评审

### 2.1 方案亮点（建议保持）
- **核心循环自洽**：三大模式形成"学习 → 创作 → 挑战"闭环，且与"搭建即乐趣"原则一致，无数值膨胀系统。
- **防挫败设计到位**：提示一次、无失败自由模式、检查点回滚，直击建造类游戏两大痛点（精度挫败、内容消耗快）。
- **文化定位清晰**："艺术还原"标注 + 官方参考图的策略，规避考古级精确的争议风险。
- **技术边界务实**：低面数、分块、异步网格、实例化的性能规划符合 Bevy 社区现状。

### 2.2 需要补强的点（已落入 BACKLOG 或 ADR）

| # | 缺口 | 建议 | 去向 |
|---|------|------|------|
| P1 | "完成度 ≥95%" 的判定标准未定义 | 按**结构层级加权**计分：台基 > 柱 > 梁 > 楼板 > 屋顶 > 装饰（装饰权重低）。避免"缺一个脊兽导致全盘不达标"的挫败；误差容差按吸附语义（位置偏差 ≤ 0.5 格）判定 | BACKLOG B-09 |
| P2 | 挑战模式"风向"机制与静态积木玩法耦合度存疑 | 风向作为**装饰性规则**（影响得分/视觉，不否决放置）；结构性玩法建议用"限时 / 限料 / 限旋转 / 结构稳定性"四类可量化规则替代 | BACKLOG B-15 |
| P3 | 蓝图匹配算法无数据结构定义 | 提前定义**稀疏格子集合**：`HashMap<IVec3, BlockId>` 表示蓝图，已放置积木取同构集合求差集 → 完成度/正确率/错误高亮一次算清。这也是 Phase 1 的核心数据结构 | ADR-005 / BACKLOG B-08 |
| P4 | 未利用物理引擎的差异化玩法 | avian3d 引入后增加"**结构稳定性挑战**"变体（积木可掉落/坍塌，评价承重合理性），是同类游戏少见的差异化亮点，且与"精准复原"形成玩法互补 | BACKLOG B-16 |
| P5 | "平均会话 ≥25 分钟"对建造类偏乐观 | 拆分指标：新玩家（教程段）≥ 15 分钟 / 老玩家 ≥ 25 分钟；补充留存类指标（D1 留存、蓝图完成率） | BACKLOG B-27（指标定义） |
| P6 | 分享码依赖云端，落地成本高 | Phase 3 明确**本地文件分享**（.ptw 存档文件）为先行路径，云端分享码后置 | BACKLOG B-21 |
| P7 | 无障碍仅一句带过 | 具体化：吸附高亮**不依赖纯颜色**（叠加轮廓/闪烁）、全功能键鼠可玩、蓝图模式提供"朗读结构提示"（Phase 3） | BACKLOG B-23 |
| P8 | 性能目标无硬件基线 | 分两档：集显档（≥ 30 FPS，≤ 5000 积木）/ 独显档（≥ 60 FPS，≤ 50000 积木）；Phase 2 压测打点 | BACKLOG B-19 |
| P9 | 中文字体未提 | Bevy 默认字体不含 CJK 字形，UI 中文需打包字体资产（Noto Sans SC 子集），列为 Phase 1 资产任务 | BACKLOG B-10 |
| P10 | 存档"二进制压缩"与分享码版本兼容 | 存档格式必须带**版本号 + schema 演进策略**（向前兼容读旧档），这是 Player 数据的底线 | ADR-006 |

## 三、量化补充（可执行的目标定义）

- **Phase 0 验收**：目标硬件（独显档）放置延迟 < 50ms、帧率 ≥ 60 FPS、无 panic 连续运行 30 分钟。
- **Phase 1 完成度公式**（B-09 落地）：`完成度 = Σ(层级权重 × 层级内匹配格子数 / 层级蓝图格子数)`，95% 达标线按此计算。
- **性能预算**：单积木 ≤ 500 三角面；单帧新增/销毁实体 ≤ 100；放置操作 O(1)（稀疏 HashMap 查重）。
