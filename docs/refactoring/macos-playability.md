# macOS 默认启动可玩性修复

2026-09-06；基线 `74b710c`。用户提供默认 cargo run 全窗口截图，文字溢出、控件重叠、HUD 遮挡。此前离屏 3D 截图和正尺寸日志不构成交互验收，本轮不沿用该结论。

## 修改前计划

1. 主执行检查 Lunex 的测量/缩放同步、文字边界及布局；先补失败回归，再作应用层修复。不改 registry、不升级依赖、不改变存档。
2. 独立调查 UI 与游戏输入隔离、点击/拖动/滚轮和撤销快捷键。具体缺陷确认后补回归修复。
3. 简化常驻 HUD：保留当前操作与教程，完整快捷键按需展开，防止长文本遮挡主要操作区域。
4. 默认模式原生全窗口验证（非 riverside 特例、非离屏截图）：可读性、四个标签、积木选择、放置/撤销/旋转、滚轮和不同窗口大小。可用工具不能覆盖的行为明确记录，不以模拟输入状态冒充人工操作。
5. 完整测试、check、Clippy、fmt、独立复核；每次视觉迭代保存真实窗口证据及 verdict。

## 本轮实现与回归（2026-09-06）

- 文本：移除 Text2d 标签的 `full()` 父级相对尺寸，统一固定字号；补充测量变化后的缩放同步，避免 Retina 字体测量与布局尺寸叠加。回归直接调用锁定版 Lunex 的测量系统。
- 标签页：列表行恢复 `Inherited` 可见性，不再穿透隐藏父级；选中积木改变时滚入可见区域，同一选择不抢回用户手动滚动。
- 点击：应用层拾取只使用专属正交 UI 相机；完整布局根不拦截全窗口点击。保留锁定版的深度、变换、可见性及阻挡语义，不修改依赖源码。
- 输入：同一帧共享 UI 所有权，鼠标手势从按下起锁定归属，拖动超过阈值后返回原点也不视为放置。UI 滚轮不缩放场景；文本输入捕获游戏快捷键，切页/外部点击释放焦点；Cmd+Shift+Z 重做不同时撤销。
- HUD：常驻内容缩减，完整帮助改为 F1 展开；移除空状态行；中文允许逐字换行。主题按钮与透明度滑杆重新分离。
- 多相机合成：3D 相机显式匹配 2D 相机 `Msaa::Off`，避免 Bevy 按不同采样数分配独立颜色纹理。此修复有组件回归，仍需原生画面证明。
- 简化：删除旧的独立点击判定状态，集中输入归属；移除本轮临时全 UI 离屏截图逻辑，不引入新依赖、不改变存档协议。

## 原生验收状态与剩余风险

Computer Use 权限曾实际生效，已获取本机原生窗口截图：巨大文字重叠问题改善，文字与标签可读；但当时场景没有显示、点击标签无响应，并有透明度重叠及 HUD 空白。这些问题随后追加了上述修复，**尚未取得修复后的完整原生验收证据**。

最后尝试重新打开原生游戏时，工具明确返回 `The Mac is locked and automatic unlock could not unlock it`。这是锁屏阻塞，不是继续修改权限或改用另一种控制工具的理由。需用户手动解锁后继续：

1. 默认启动确认 3D 可见，且镜头构图、HUD 高度和主题/滑杆布局可用。
2. 点击四个标签，检查隐藏内容不串页；教程默认选择应出现在积木列表中。
3. 放置、撤销、Cmd+Shift+Z 重做、旋转；拖动镜头不能误放置。
4. 列表滚轮与场景缩放隔离，存档输入焦点捕获及外部点击恢复快捷键。
5. 调整窗口大小并检查 Retina 布局，重新记录 visual-verdict。

当前不宣称“游戏已可玩”，不以构建和单元测试替代以上验收。锁定依赖升级时必须重新核对拾取适配器与文字缩放同步。

## 原生解锁后第二轮计划与证据（2026-09-07）

- 已看到恢复的 3D 场景；原生鼠标进入标签造成进程退出，macOS 崩溃栈证实 Lunex 0.7 的 `UiHoverSet` 子级复制未改 target，形成无限递归。应用层直接更新悬停状态，避免发送这一上游事件；新增事件计数回归，先失败后通过。
- HUD 的百分比最大宽度在文字内在测量时再次约束宽度，造成 90px 文字撑出 204px 面板。用视口宽度单位替代父级百分比，真实 Taffy/字体测量回归覆盖 1x/2x 和 640/1280 宽度，已复现红灯。
- 后续改动前计划：仅在启动时按蓝图边界取景，保留玩家后续相机控制与 riverside 的覆盖；先写投影边界测试。重启本轮测试进程，逐项验证点击、输入隔离、放置与撤销，不把 CUA 连接失败直接判定为游戏死锁。
- 卡顿采样只有两次采样命中有界的 placement 扫描，不足以证明死锁；稍后的窗口已有旋转/跳过教程变化。因此不据此大改放置算法，先恢复原生控制连接再判断。
