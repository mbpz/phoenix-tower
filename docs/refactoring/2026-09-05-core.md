# 游戏核心重构计划

## 范围与约束

保留现有 Rust / Bevy / Lunex 技术栈、画面布局、快捷键、主题资源与 v1 存档格式；不引入依赖，不做整套视觉重设计。优先修复影响长时间搭建的数据边界，再按职责拆分文件。

## 已确认的问题

1. `PlacedBlocks.records` 同时充当完整建筑与 20 步历史；第 21 次放置会销毁最早的实体，导致大型建筑、30 块成就与存档不完整。
2. 放置、撤销、拆除、读档、挑战重置各自修改占用表、列顶和 revision；读档没有清空 redo。
3. 灯笼/匾额对账用子实体标记排除父实体，每次 revision 变化都会重复挂载子实体。
4. `ui/lunex.rs` 混合布局、交互、存档、挑战、图鉴及开发探针，修改边界不清晰。

## 执行顺序（测试优先）

- 基线：运行现有测试，记录编译、格式与静态检查的既有问题。
- 行为锁定：先增加占用、撤销/重做、导入与装饰生命周期的回归测试；已知缺陷使用失败测试证明。
- 数据边界：抽取 `building/world.rs`，完整 records 不受历史上限影响；20 步历史独立记录可撤销实体。统一记录插入/移除、占用索引、清空、恢复和版本号。移除不再使用的重复维护逻辑。
- 渲染边界：抽取装饰挂载逻辑，保证每块灯笼/匾额只生成一次对应子实体，随父实体销毁。压力积木继续排除。
- UI 边界：保持注册顺序、观察者与 public 路径兼容，按职责抽取实际有意义的模块；先测试已有纯逻辑/无窗口系统，不创建通用框架。
- 验证：完整测试、cargo check、cargo fmt --check、cargo clippy，尽可能运行原生冒烟测试。未运行的 GPU/人工交互验证明确记录。

## 回归验收

- 放置超过 20 块不丢失建筑，保存完整建筑；只能撤销最近 20 次放置。
- 撤销/重做保持 cells、col_top、records 与 revision 一致；新放置和拆除清除失效 redo，导入/重置清空历史。
- 导入后不再重做上一个世界的数据；旋转与存档 round-trip 不变。
- 无关建筑变化不重复生成灯笼/匾额子实体；复原后的新父实体可重新装饰；压力块不装饰。
- UI 模块拆分不更改用户可见布局、快捷键和按钮行为。

## 有意延后

整体美术升级、挑战规则重设计、物理参数调整、引擎升级、Web 迁移、完整输入焦点治理和无关模块格式化。

## 独立评审后的约束补充

- 撤销 ID 唯一、最多 20 个且只能引用存活记录；淘汰历史仅删 ID。重做重建实体后登记新 ID，不清空剩余 redo。物理复原按顺序重映射 undo 引用，保留 redo 数据，不调用 replace_all。
- `occupied` 始终为全部存活记录 cells 的并集，`col_top` 由该并集推导。兼容现有重叠导入；删除后重建索引，避免误释放其他积木仍占用的格子。
- world API 只管理数据。调用方继续负责生成/销毁实体，读档和挑战保留 query 清理（包含不在 records 中的压力实体）。
- 每次成功的逻辑变更（含批量替换、实体复原）只递增一次 revision；无效撤销/重做不改变版本。挑战配额与蓝图刷新仍由玩法系统处理。
- 读档是新编辑会话：清空先前 undo/redo，导入的积木作为建筑基线，不自动变为玩家的撤销命令。存档格式不保存历史，保持 v1 兼容。
- 补充回归：重叠记录删除、非空世界导入后的 ECS 生命周期、放置→撤销→物理复原→重做→撤销、挑战配额不足时重做无副作用。

## 完成与验证记录

### 实际改动

- `src/building/world.rs`：独立完整建筑与有界撤销历史，集中维护占用并集、列顶、revision 和重建实体引用。
- `src/building/decorations.rs`：父实体一次性挂载标记与装饰生命周期；替代两个依赖世界 revision 的重复对账系统。
- `src/building/placement.rs`、`src/save/mod.rs`、`src/building/challenge.rs`、`src/stability.rs`：迁移至统一数据变更入口，保留各调用方的 ECS、配额及蓝图副作用。
- `src/building/mod.rs`：注册新模块；原有 placement 导出路径保留兼容。
- `src/ui/lunex.rs`：从 2566 行缩减为 96 行插件注册入口；实现移至 `lunex/{layout,palette,saves,challenges,collection,probes}.rs`，无窗口回归放入 `lunex/tests.rs`。保持系统注册、观察者和 UI 子树顺序，不以总行数减少冒充职责拆分收益。
- 复杂 ECS 查询使用语义化局部类型别名；没有新增 lint 屏蔽。严格 Clippy 同时发现 `meshes.rs` 的两个既有小问题，删除未使用的 enumerate 索引和错位文档注释，网格算法不变。
- `README.md`：同步模块结构与新的历史/导入语义。
