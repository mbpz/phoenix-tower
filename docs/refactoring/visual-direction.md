# 视觉方向：从体素演示到中式微缩庭院

日期：2026-09-07。本文是针对当前代码和本机画面的工程方案，不是已实现的效果承诺。

## 判断与取舍

保留 Bevy 和现有搭建、撤销、存档逻辑；采用 Blender 制作的模块化建筑资产，先做一个完整的风格化中式微缩庭院。不要继续以透明小方块和灰色大平面作为正式美术，也不要以换引擎代替资产、灯光和构图设计。

本机已存在 Blender，项目已有 `tools/build_riverside_assets.py`、六种 GLB 模块及 `.blend`。但当前入口默认仍是程序化网格；GLB 仅在 `--riverside` 模式为少量积木加载。加载器只取 primitive 0，并使用游戏侧材质；现有导出以顶点色、单网格为主，尚无正式的多材质/PBR 贴图管线。**不是把 Blender 导出模型放进目录，就会自动得到成品游戏画面。**

## 建议的第一份交付：一座可搭建亭子 + 小庭院

| 方面 | 当前短板 | 小场景实施方向 |
| --- | --- | --- |
| 建筑 | 立方体堆叠、轮廓弱 | 手工校准屋顶曲线、飞檐、斗拱比例；柱梁倒角；构件保持搭建接口 |
| 材质 | 单色、石木瓦区分弱 | 分开石材/木材/琉璃瓦；基础色、粗糙度、法线、烘焙 AO；先少量可复用材质 |
| 光照 | 灰暗、主体与地面混在一起 | 单一暖主光与冷环境光、清楚的接触阴影；昼夜各一个明确构图，不堆高成本屏幕特效 |
| 环境 | 大灰平面和占位山丘 | 有边界的石台、庭院、水岸与少量植被，形成尺寸和距离参照 |
| 蓝图 | 整楼透明格子像调试网格 | 仅显示当前步骤；整件轮廓/低透明预览；占位格和碰撞仍保留作内部逻辑 |
| 相机/UI | 建筑是背景，说明区抢主体 | 以操作区为中心的固定倾斜视角，可旋转检查；按当前构建高度取景；说明只在需要时显示 |

加载管线先处理多 primitive/多材质、变换和包围盒映射，不能直接丢弃旧网格尺寸与吸附/存档兼容。正式资产未加载时应明确提示开发状态；不要靠静默回退方块冒充成品。

## 验收必须在游戏里

1. `cargo run` 能直接进入这一个场景，而非必须知道隐藏的模式参数。
2. 在本机 Retina 窗口的总览、近景、夜景三种视角验收；以原生运行截图为准，不以 Blender 静帧代替。
3. 完成从台基到屋顶的完整放置、旋转、拆除、撤销和重新载入闭环；所有可操作目标可见。
4. 场景建设目标为前台稳定 60 FPS，后台约 10 次/秒空闲更新。测量真实帧时分布、CPU、内存和渲染批次；这是验收目标，不是当前已达到。
5. 先给一座亭子建立可重复基准，再扩展黄鹤楼五层与完整资源集。模型精细化不能以数倍 CPU/GPU 成本为代价。

## 引擎选择边界

- **推荐当前路线：Bevy + Blender 美术资产。** 最大限度复用已有玩法，以一个小场景验证视觉质量和成本后再扩展。
- 如果后续明确要求大量关卡编辑、非程序成员独立搭场景，应另做编辑器工作流/迁移成本评估，再考虑 Godot 或 Unity；不在性能修复过程中直接搬家。
- 不建议此时同时迁移重型引擎并追求写实开放场景，这会引入新的性能和玩法回归变量，也不能保证美术质量。

本轮只确定路线，不新增依赖、不下载外部美术、不声称已经完成高质量视觉重构。外部官方文档检索未返回可用内容，本文不据此声称任何引擎的最新版本能力。
