# macOS 性能优先修复与视觉路线（2026-09-07）

## 修改前计划

用户报告调试游戏接近 300% CPU，优先于尚未完成的交互验收。保留此前未提交修复，不改写已推送历史，不新增依赖。

1. 对现有进程采样 CPU/线程栈，区分前台、后台、帧率与调试构建，保留旧二进制作同场景对照。
2. 先补回归，再修复默认无限更新和后台无节流的问题；使用睡眠而不是忙等，保留正常输入处理、截图和压力测试显式无上限出口。
3. 清除有证据的静态场景重复更新，避免不变的材质/灯光每帧标记为修改；验证昼夜过渡和首帧初始化。
4. 同一设备、同一场景、同一构建配置复测，不把编译器耗时、失焦数据或帧数差异伪装成 GPU 优化。
5. 视觉路线先审查现有资产与可复用管线，提出独立、可验收的小场景方案；本轮不直接换引擎或批量引入高成本资产。

## 初始证据

- 旧进程 PID 26183，7 块 / 41% 教程后场景；`ps` 一次采样 173.5% CPU。后续 `top` 末次 63.8%，焦点状态未锁定，不能作为严格 A/B 基线，也未复现用户的精确 300%。
- 原生 HUD 此前显示过 128 / 230 FPS；主入口没有显式帧率预算，依赖默认窗口与 Winit 调度。截图相机默认停用，不是持续双相机渲染。
- `/tmp/phoenix-cpu-before.sample.txt` 是 5 秒采样；大量工作线程等待/调度栈，不能仅以出现次数认定具体游戏系统为最大热点。
- `day_night_system` 在白天/夜晚完全静止时仍逐帧修改灯光、材质、雾和清屏色，值得用变更检测回归消除无效更新。

## 调度方案迭代

第一版在 Last 睡眠，第二版改为 First 开始到开始预算。原生前台仍约 48–55 FPS，而对照约 55–73；CPU 差异不足以证明净收益。拒绝将此作为最终策略：移除自定义主线程睡眠，复用 Winit 事件循环的 reactive_low_power 等待（前台空闲 60Hz / 后台 10Hz），输入可以提前唤醒。这里是空闲刷新策略，不是交互中的硬 FPS 上限；需要复测，不能继续声称严格限帧成功。先加插件配置回归确认默认旧 Continuous 失败。

## 最终实现与验证

- `src/performance.rs`：复用 `WinitSettings`；前台空闲周期 1/60 秒，失焦空闲周期 100ms，忽略无关原始设备事件。**输入/窗口事件可以提前唤醒，非硬帧率上限。** 没有自定义睡眠、忙等、线程或新依赖。
- `PHOENIX_UNCAPPED=1 cargo run` 仅供基准：前后台均切回 Continuous；VSync 仍有效。普通使用不设置该变量。
- `src/scene/mod.rs`：不变的太阳、环境光、清屏色、雾、灯笼光强与发光材质不再反复标脏；保持昼夜过渡和夜间新灯初始化。
- `src/building/tutorial.rs`：仅实际切换积木时写入当前选择，避免空闲教程每帧触发 BlockLibrary 下游 UI 工作；选择被改变后仍强制纠正教程目标。

### 本机测量（全部为同一 dev 配置，不是 release）

1280×752 原生窗口、Retina scale 2，空教程 0 块。前台对照为同一初始相机；最小化测量在拖动验证之后，不能视为完全相同渲染视角。无编译任务与这三个正式窗口重叠。每轮 `top` 8 次、2 秒间隔，丢弃第一次无意义的 0；短窗口不能消除其他应用、热状态、知识提示轮换和 OS 调度噪声。

| 状态 | CPU 七次样本均值 / 范围 | 帧率（每秒一次瞬时样本，非帧时分位数） |
| --- | --- | --- |
| 修改前前台，14:54:42–14:54:57 +08 | 61.29% / 45.7–82.0% | 54.5–73.4 |
| 最终事件循环版前台，15:34:08–15:34:23 +08 | 68.31% / 55.2–82.1% | 56.1–61.9，中位数约 60 |
| 最终版最小化，15:38:39–15:38:54 +08 | 25.87% / 19.6–28.3% | 中位数约 10，末次唤醒样本 19 |

结论：后台等待生效；前台恢复约60 FPS，拒绝了此前自定义睡眠约50 FPS的退化。但**前台 CPU 未证明下降**，不能根据当前55–82%声称已从用户300%降到这些数值。300%峰值未受控复现，性能总验收仍为 partial。早期173.5%是另一时刻/7块场景的单次读数，不混入这个表。当前修复是调度与无效更新止损，不是完整性能问题结案。

完整样本：`.omx/state/macos-performance/measurements.json`；原始记录在 `/tmp/phoenix-perf-event-*.top.txt` 与 `/tmp/phoenix-perf-event-native.log`。JSON 保留被拒绝的睡眠版本数据，防止后续误当最终成果。
