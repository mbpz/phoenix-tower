# ADR-007：渲染性能策略（实例化优先，分块网格化按需）

- 状态：已接受（2026-08，B-20 实测）
- 关联：docs/PRD.md §4 分块与性能、BACKLOG B-20

## 背景

PRD §4.3 预设"分块 + 脏标记 + 异步贪婪网格化"。实际架构为模块化积木（非纯体素），
每积木一个实体，但**网格与材质按积木定义共享**（BlockRenderAssets 预生成，所有同型
积木引用同一 Handle）——Bevy 0.19 的 GPU 预处理会自动实例化同网格同材质的批次。

## 实测（Apple M1 集显，debug 构建，PHOENIX_STRESS 压力模式）

| 积木数 | 实测 FPS |
|--------|----------|
| 10,000 | ~250 |
| 30,000 | ~160 |
| 50,000 | ~105-130 |

## 决策

1. **共享资产 + 自动实例化是当前性能支柱**：不做分块网格化也能满足
   B-20 验收（独显档 50000 ≥ 60 FPS，集显档已 2 倍达标）。
2. **分块/贪婪网格化降级为按需优化**：仅当单场景 > 10 万积木或移动端
   低端设备出现瓶颈时再引入；届时按 PRD 方案实现脏标记 + 异步网格。
3. **每帧 O(n) 扫描已消除**：集合图鉴扫描按 PlacedBlocks.revision 门控
   （世界未变更不重扫）。
4. 压力模式（`PHOENIX_STRESS=<n>`）作为回归基准保留在 CI/发布前检查。

## 后果

- 优点：以最少改动满足目标；避免为不存在的瓶颈引入复杂网格系统。
- 成本：超大世界（>10 万块）需要后续评估；开发期基准环境为本机 M1。
