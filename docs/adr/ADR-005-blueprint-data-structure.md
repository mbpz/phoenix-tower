# ADR-005：世界数据结构与蓝图匹配（稀疏格子集合）

- 状态：建议（Phase 1 落地时接受）
- 关联：docs/PRD.md §3.1/§4、docs/REVIEW.md P3、BACKLOG B-08/B-09

## 背景

蓝图模式的完成度/正确率/错误高亮需要一个统一的数据结构；方案 §4 只写了"稀疏 HashMap 或 Octree"，未定义蓝图匹配算法。

## 决策

1. **世界积木表**：`HashMap<IVec3, PlacedBlockEntry>`（稀疏格子 → BlockId + 旋转 + 实体句柄）。放置/删除 O(1) 查重，天然满足 ADR-003 的网格放置性能要求。
2. **蓝图表**：`HashMap<IVec3, BlockId>`（蓝图格子 → 期望积木）。同构集合求差集：
   - `蓝图 ∩ 已放置(匹配)` = 正确格子 → 完成度/正确率
   - `蓝图 - 已放置` = 缺失格子 → 幽灵提示高亮
   - `已放置 - 蓝图` = 多余格子 → 错误高亮（蓝图中）
3. **完成度加权**（REVIEW P1）：`完成度 = Σ(层级权重 × 层级匹配率)`，层级权重：台基 0.25 / 柱 0.25 / 梁 0.2 / 楼板 0.1 / 屋顶 0.15 / 装饰 0.05（草案值，美术/策划可调）。
4. 旋转匹配：蓝图中可旋转部件按"存在任意 90° 合法旋转"计为匹配，45° 旋转仅限自由模式。

## 后果

- 优点：完成度、正确率、错误高亮、幽灵提示一次算清，算法纯函数可单测。
- 成本：需要专门的单测矩阵（对齐/偏移/旋转/多余积木四种情形）。
